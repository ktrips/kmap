# 更新履歴

Komap（iOSアプリ）の主な機能追加・変更の記録です。詳しい仕様は [README](../README.md) を参照してください。

## 2026-09 古地図・AI・写真・動画まわりの更新

### 公開旅は旅のフラグだけで切り替え、処理はクラウドで
- 旅の正本は`users/{uid}/walkRoutes`の1か所。公開・非公開は`isSharedPublicly`だけで切り替え、公開用のコピー
  （`sharedTrips`の中身・`sharedPhotos/`の写真の複製）は作らない。御朱印・投稿写真は旅の公開状況に従う
  （写真ごとの「公開／非公開」は廃止）。
- 公開ページ用の投稿者名・写真の一覧・いいね/コメントの件数は Cloud Functions が旅の文書に書く。
- 同じGoogleアカウントで別の端末に記録した旅・御朱印・写真を、起動・サインイン時に取り込む。
- **デプロイが必要**: `firebase deploy --only functions,firestore:indexes` → 管理者で`migrateSharedTrips`を実行 → `main`へマージ。

### マイ時空旅・マイ御朱印はサインイン中のアカウントの記録だけ
- 旅・御朱印・投稿写真に保存したアカウント（`ownerUserID`）を持たせ、「マイ時空旅」「マイ御朱印」・ポイント・
  地図には、サインイン中のアカウントで保存したものだけを出す。御朱印の獲得済みの判定もアカウントごと。
- これまでの記録は、サインインした時にクラウドに同じIDがあるものを、そのアカウントのものにする。
- 「設定」のクラウド同期で、別のアカウントの記録を今のアカウントのクラウドへ上げていた問題も解消。
- 設定画面: 「アカウント / Web連携」を一番上に（その中に Komap Plus）、「歩行中の設定」カードにまとめた。

### Komap Plus のプロモユーザー
- 管理者だけが、購入しなくても Plus を使える人（プロモユーザー）をメールアドレスで登録・削除できる
  （Webの管理者レポート）。登録された人は、iOSアプリ・Webの Kindle本の全文で Plus として扱われる。
- 「Plus に登録する」ボタンが、商品を取得できない時に無反応だったのを修正（理由を表示する）。
  Xcodeから実行した時にローカルの商品で購入を試せる StoreKit 設定ファイルを追加。

### 管理者は無料で Komap Plus
- 管理者のアカウントでサインインしている間は、購入しなくても Plus の機能（写真・場所の詳細・旅の動画・
  AIの旅日記・Webの Kindle本の全文）を使える。比較ページには、その旨を表示する。

### Komap Plus（サブスクリプション）
- 月額480円／年額3,800円（初回7日間無料）の Komap Plus を追加。「設定」の一番上から、
  無料版との比較ページを開ける。
- 写真の追加とAIの旅日記の作成は Plus のみ。場所の詳細は無料で3か所まで、旅の動画は無料で1本まで。
  使い切った後に使おうとした時や、初めて旅を保存した時に比較ページを開く。
- Web版のKindle原稿は、無料では冒頭（約10ページ）、Plus の人はサインインすると全文を読める
  （Cloud Function が App Store Server API で購入状態を確かめてから本文を返す）。
- Kindle本の原稿（全文のMarkdown・Word・PDF）をリポジトリから外した（`private/`、.gitignore済み）。

### パフォーマンス改善（リストの候補をすべて実施）
- 古地図の画像31枚をPNGからJPEGに（52.9MB → 10.4MB）。
- Watchの位置送信を3秒ごとにまとめる。自動一時停止から歩き出した時にWatchの画面を「記録中」に戻す。
- いいね・コメントの件数を公開データに持たせ（Cloud Functionsで更新）、一覧の集計クエリをなくした。
- Webの公開ページは軽量版のFirestoreを使い、最初に読み込むJSを約33%減らした。
- 古地図・チェックポイントの一覧を`catalog/*.json`にまとめ、iOS・Webのデータは生成する形にした。
- 中国の古地図を、Google マップの背景（GCJ-02）に合わせて表示する。

### 重複・無駄な処理の整理（2回目）
- 古地図・チェックポイントの一覧がiOSとWebで食い違っていた（銀座・歌舞伎座の古地図と7か所がWebに無く、
  Webで古地図が重ならず御朱印名も出なかった）のを修正。食い違いをCIで検出する
  `scripts/check-catalog-sync.mjs`（`.github/workflows/catalog-sync.yml`）を追加。
- Watch⇄iPhoneの返信を求めないメッセージの受け口が無く、Watchの現在地の送信が毎回失敗していた
  （コマンド・通知も再送で遅れていた）のを、両側に受け口を追加して修正。
- 公開データの作り直しで、前回コピー済みで元の写真が変わっていない写真はコピーし直さない。
  写真があるかの確認に、画像を読み込まずファイルの有無だけを見る（`StampPhotoStore.exists`）。
- 旅日記: 一覧のサムネイルに縮小版を使う。御朱印の説明は画面を開いた時に一度だけ読む。
- 旅の詳細: 御朱印・投稿写真をデータベース側でその旅の分だけ取得する。旅日記の更新有無の確認で、
  描き直しのたびにデータベースを読まない。
- 「設定」のクラウド同期で、取り込み済みの名前・感想を旅ごとに読み直さない。
- 距離・時間・日時の書式を`TripFormat`（iOS）・`format.ts`（Web）に集約。
- Web: 公開ページとサインイン後の画面で重複していた、一覧の開閉・旅の選択・ホームに戻る処理を
  `useTripBrowser`に集約。古地図・チェックポイントのID検索を索引化。

### 旅の動画の作り直し・Webの公開データの更新
- iOS: 時間旅の詳細の「動画を再生」の横に「作り直す」ボタンを追加（長押しメニューからも作り直せる）。
- iOS: 端末に動画があるのにクラウドのリンクが無い旅は、詳細を開いた時に動画を上げ直す。
- iOS: 「設定」のクラウド同期で、公開中の時空旅すべての公開データ（`sharedTrips`）を最新の内容
  （動画・御朱印の説明・写真）で作り直す。公開データは公開した時点のコピーのため、その後に作った
  動画や説明がWebに出ていなかった。クラウドに上がっていなかった写真も、この時に上げてから公開する。

  （「別のタブで開く」は廃止）。

### パフォーマンスの改善・重複の整理
- iOS: 時空旅の総距離を、参照のたびに軌跡全体から計算し直していたのをやめ、点の数が変わった時だけ
  計算して覚えておく（「My Trips」のポイント集計・一覧の各行で何度も参照していた）。
- iOS: 「My Trips」で、時空旅ごとの御朱印の件数を行ごとに全件数え直さず、1回だけ数える。
- iOS: 「全ての古地図を表示」中、GPS更新のたびに行っていた表示対象の絞り込みと、約70枚分の
  重ね直し判定を、古地図の一覧か設定が変わった時だけ行うようにした。チェックポイントのID検索も索引化。
- Web: 時空旅一覧の各行で、いいね・コメントを2本ずつリアルタイム購読していた（最大100本）のをやめ、
  集計クエリで1回数えて短時間キャッシュする（iOSアプリと同じ方式）。
- Web: 閲覧人数の生存確認と数え直しを、タブが裏に回っている間は止める。
- Web: Cloud Functions・AnalyticsのSDKを初回読み込みから外し、使う時だけ読み込む。
- Web: `walkRoutes`と`sharedTrips`の読み取り処理、日付・距離の表示書式の重複を1か所にまとめた。
  御朱印・投稿写真の時空旅ごとの振り分けを、旅ごとの全件絞り込みから1回のグループ化に変更。
  使っていないテンプレートの画像（`vite.svg`）を削除。

### Webで旅の動画を再生
- iOSアプリで作った旅の動画があれば、Webの時空旅の詳細に「旅の動画」を表示し、その場で再生できる
  （旅日記の末尾の動画リンクは重複するため本文からは外す）。

### 時空旅の名前・感想の同期、地図から動画を再生
- Webで変えた時空旅の名前・感想が、iOSアプリに反映されない不具合を修正。iOSアプリは`walkRoutes`を
  上げるだけで取り込んでいなかった。「My Trips」を開いた時に取り込み、変更日時（`detailsUpdatedAt`）で
  新しい方を残す。iOSで変えた名前・感想も、公開していない旅を含めて`walkRoutes`へ上げるようにした。
- 旅の動画を作った旅では、時間旅の詳細画面・旅日記の地図を押すと動画を再生する。

### Apple Watchの電池消費を抑える
- 一時停止中はWatchのGPSを止める（自動一時停止中は精度を落として動き出しだけを見る）。
- 最長8時間・動きがない時の自動一時停止を、静止中でも30秒ごとに判定するようにした
  （これまではGPSの更新が来ないと判定されず、記録が止まらないことがあった）。
- 一時停止のまま1時間たったら、それまでの軌跡を保存して記録を終える。
- iPhoneが記録中に30秒ごとに送る生存確認が90秒以上途絶えたら、Watchの伴走のGPSを止める。
  iPhoneのアプリが落ちた時の古い「記録中」の状態で、伴走が始まり続ける不具合を修正。
- iPhoneのアプリを終了させても、Watchの伴走が止まらない不具合を修正。記録していない時の状態に
  空の値（NSNull）が入り、Watchへの状態の送信が毎回失敗していたため、Watchに「記録を終えた」が
  届いていなかった。あわせて、アプリが終了させられる時にもWatchへ「記録していない」を送る。
- ワークアウトが外から終了された時・Watchアプリが記録中に落ちた時も、ワークアウトとGPSを止める。
- HealthKitの許可を待つ間に記録を終えると、誰も止めないワークアウトが残る不具合を修正。

### 古地図の選択・表示
- 「古地図を選択」の先頭に、コンパクトなクイックボタン「現在地」「新地図」「全地図」「地図無し」を追加。
  「現在地」は現在地を含む古地図を自動選択し、画面の中心も現在地へ移動する。
- 各地図の右側に詳細アイコン（ⓘ）を追加。詳細画面と、マップ上部中央の地図名から開く説明シートを
  同じ形式（画像＋番号つきチェックポイントのピン＋説明）に統一。歩行中も説明を開けるようにした。
- 設定の「最初に表示する古地図」で「現在地」「全地図」も選べるように（未設定は「現在地」）。
- 歩行中の進行方向の矢印を、現在地マークの縁から少し離して表示。
- メインの地図をタップしてポイントを追加する機能を廃止（追加は編集画面の中だけ）。

### 新しい古地図の検索・作成・編集
- 古地図の画像検索を、Googleカスタム検索（ブロックされるため）から、
  国立国会図書館デジタルコレクション（IIIF）と Wikimedia Commons（どちらもキー不要）に変更。
  管理者設定とGoogleカスタム検索の設定項目を廃止し、「新しい地図を追加」とGoogle Mapsの設定状況は
  「AI設定」へ移動。
- 画像が見つからない時は、AIが条件に合わせて範囲とチェックポイント5件を作り、古地図風の
  レイヤーで代用。
- 検索範囲の限定（現在の範囲／周囲5km／周囲10km）と、ファンタジー地図の生成（AIの画像生成）を追加。
- 追加した古地図の編集（ポイントの追加・削除、地図名変更、公開範囲、AIによる「地図をアップデート」、削除）。
- 追加した古地図のクラウド公開・取り下げ・取り込み（`sharedOverlayMaps`）と「みんなの古地図」一覧。
  **デプロイが必要**: `firebase deploy --only firestore:rules,storage`
- 管理者（`kenichiyoshida13@gmail.com`）は同梱の古地図も編集可能（端末内の「上書き」として保存）。

### パフォーマンス・開発環境
- 地図の描画フレームレートを60Hzに、建物・屋内地図の描画を停止。追加した古地図の画像は
  1024×1024pxに揃えて保存。古地図・チェックポイントの参照をID索引とキャッシュ化。
- `scripts/clean-derived-data.sh`: KomapのDerivedDataを削除するスクリプト。launchdで毎日04:00に
  実行する設定（`~/Library/LaunchAgents/net.ktrips.komap.clean-derived-data.plist`）を別途用意している。
- 新しいSwiftファイルを追加した後は `xcodegen generate` でプロジェクトを再生成する。

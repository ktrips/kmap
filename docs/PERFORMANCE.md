# パフォーマンス改善・不具合メモ

アプリ（iOS・Apple Watch）とWebの、パフォーマンス改善・重複の整理・見つけた不具合の記録です。
改善や調査をするたびに、ここに「実施内容」「結果」を書き足し、見つけた重複・不具合・今後の候補も残します。

- `[x]` 実施済み　`[ ]` 未実施（今後の候補）
- 結果は、測ったもの・確かめたことだけを書く（未確認のものは「未確認」と書く）

---

## 1. 実施済みの改善

### Apple Watch の電池（2026-09-26）

- [x] 一時停止中は GPS を止める（手動）／精度を落として動き出しだけを見る（自動一時停止）
  - 結果: 一時停止中の GPS が最高精度で動き続けることがなくなった。実機での電池消費の比較は未確認
- [x] 最長8時間・動きがない時の自動一時停止を、GPS の更新が来ない静止中も30秒ごとのタイマーで判定
  - 結果: 静止していると記録が終わらない不具合を解消
- [x] 一時停止のまま1時間たったら、軌跡を保存して記録を終える
- [x] iPhone からの生存確認（30秒ごと）が90秒途絶えたら、Watch の伴走 GPS を止める
- [x] iPhone のアプリが終了させられる時に「記録していない」を Watch へ送る
- [x] 記録中に Watch アプリが落ちて残ったワークアウトを、次の起動時に回収して終える
- [x] HealthKit の許可を待つ間に記録を終えた場合に、ワークアウトを始めない
- [x] Watch の位置送信を、GPS の更新（5mごと）のたびではなく3秒ごとにまとめて送る（2026-09-27）
  - 結果: 送信回数は、歩く速さ（約1.3m/秒）なら約4回に1回になる計算。実機での電池の比較は未確認。
    iPhone 側は古い版の Watch（1点ずつ）の送信も読める

### アプリ・Web の処理（2026-09-26〜27）

- [x] iOS: 旅の総距離を、点の数が変わった時だけ計算して覚えておく（`WalkRoute.totalDistanceMeters`）
  - 結果: 以前は参照のたびに全区間を計算し、1区間ごとに `CLLocation` を2つ作っていた。My Trips の描画のたびに全部の旅で何度も計算していた
- [x] iOS: My Trips の御朱印の件数を、行ごとではなく1回でまとめて数える
- [x] iOS: 「全地図」表示中の古地図の絞り込みと貼り直しの判定を、一覧か設定が変わった時だけ行う
- [x] iOS: チェックポイントの ID 検索を索引化
- [x] iOS: 旅日記のサムネイルに縮小版を使う。御朱印の説明は画面を開いた時に1回だけ読む
- [x] iOS: 旅の詳細画面で、その旅の御朱印・写真だけをデータベースから取得する
- [x] iOS: 旅日記の「新しい情報があるか」の確認で、描き直しのたびにデータベースを読まない
- [x] iOS: 公開データを作り直す時、元の写真が変わっていなければ前回のコピーを使い回す
  - 結果: 以前は名前の変更などのたびに、全写真をダウンロードしてアップロードし直していた
- [x] iOS: 写真があるかを、画像を読み込まずにファイルの有無で判定する（`StampPhotoStore.exists`）
- [x] iOS: クラウド同期でまとめて上げる時、旅ごとのクラウドの読み込みを省く（`checkRemoteDetails: false`）
- [x] Web: 旅の一覧の各行が、いいね・コメントを常時監視していた（最大100本）のを、件数だけを1回数えて1分間キャッシュする方式に変更
- [x] Web: 閲覧人数の生存確認と数え直しを、タブが裏に回っている間は止める
- [x] Web: Cloud Functions・Analytics の SDK を、使う時だけ読み込む
  - 結果: 最初に読み込む Firebase のファイルが 592KB → 566KB（圧縮後 176KB → 168KB）
- [x] Web: 古地図・チェックポイントの ID 検索を索引化
- [x] Web: 公開ページは軽量版の Firestore（`firebase/firestore/lite`、リアルタイム更新なし）を使い、
  リアルタイム更新が必要なサインイン後の自分の記録だけ、完全版を初めて必要になった時に読み込む（2026-09-27）
  - 結果: 最初に読み込む JS（アプリ本体＋React＋Firebase）が 856KB → 555KB（圧縮後 259KB → 173KB、約33%減）。
    Firebase のファイルは 566KB → 241KB。完全版（517KB）は公開ページでは読み込まれないことをブラウザで確認
  - 変わった動き: 公開ページの旅の一覧・いいね・コメントはリアルタイムでは更新されない（開いた時と、
    自分が操作した後、5分以上たってタブに戻った時に読み直す）。サインイン後の画面は手元で未確認
- [x] いいね・コメントの件数を公開データ（`sharedTrips.likeCount`・`commentCount`）に持たせた（2026-09-27）
  - 内容: いいね・コメントが増減するたびに Cloud Functions（`syncTripLikeCount`・`syncTripCommentCount`、us-central1）が
    数え直して書き込む。Web・iOS の一覧は件数があればそれを使い、無い旅だけ従来どおり集計クエリで数える。
    既存の公開中の旅14件には、手元から一度だけ件数を書き込んだ
  - 結果: 一覧を開いた時の集計クエリが「公開中の旅の数×2本」（今は28本）から0本になった（14件とも件数あり）。
    書き込んだ件数は、以前の一覧の表示と一致することを確認

### アプリのサイズ（2026-09-27）

- [x] 古地図の画像31枚を PNG から JPEG（品質85）に変更
  - 結果: 画像の合計 52.9MB → 10.4MB。ビルド後のアプリ内の画像ファイル（Assets.car）は 11MB。
    元の PNG に透明部分のある画像は無かった（確認済み）。江戸城の画像を拡大して PNG と比べ、違いは見られなかった

### 重複の整理

- [x] 距離・時間・日付の表示の処理を `TripFormat`（iOS）・`format.ts`（Web）にまとめた
- [x] Web: `walkRoutes` と `sharedTrips` の読み取り処理を `parseTripFields` にまとめた
- [x] Web: 公開ページとサインイン後の画面の、一覧の開閉・旅の選択の処理を `useTripBrowser` にまとめた
- [x] 使っていないテンプレートの画像（`web/src/assets/vite.svg`）を削除
- [x] 古地図・チェックポイントの一覧を`catalog/old_maps.json`・`catalog/historic_sites.json`だけで管理し、
  iOS（`Komap/Models/Generated/`）と Web（`web/src/lib/generated/catalogData.ts`）のデータファイルは
  `scripts/generate-catalog.mjs`で生成する（2026-09-27）
  - 結果: 変更前と生成後で、古地図32枚・チェックポイント210か所の値（順番を含む）が iOS・Web とも一致することを確認。
    地図ごとの出典・位置合わせのメモも生成ファイルに残る。CI（`catalog-sync.yml`）は生成し忘れを検出する
- [x] Web: 地点・時空旅・御朱印・投稿写真の4つのリアルタイム購読の処理（ほぼ同じコード）を
  `useRealtimeCollection`にまとめた（2026-09-27）
- [x] リージョンを切り替えた時の後始末（既定の古地図・表示中の古地図を戻す）を、「設定」と「古地図を選択」の
  両方に書かず`MapSessionState.changeRegion`にまとめた（2026-09-27）

## 2. 見つかった不具合・重複（記録）

| 状態 | 内容 | 原因 | 対応 |
|---|---|---|---|
| [x] 修正済み | iPhone で記録を終えても・アプリを終了しても、Watch の伴走 GPS が止まらない | Watch へ送る状態に空の値（NSNull）が入り、送信が毎回失敗していた | 空の値を入れない。終了時にも通知 |
| [x] 修正済み | Watch から iPhone へのリアルタイムの位置送信が毎回失敗 | 返信を求めないメッセージの受け口が iPhone 側に無かった | 両側に受け口を追加 |
| [x] 修正済み | Web で変えた旅の名前・説明がアプリに反映されない | アプリがクラウドから読み込んでいなかった | 取り込みと、変更日時での新旧の判定を追加 |
| [x] 修正済み | 古地図・チェックポイントの一覧がアプリと Web でずれていた（銀座） | 二重管理 | 追加し、CI（`scripts/check-catalog-sync.mjs`）で検出 |
| [x] 修正済み | Web で旅の動画・御朱印の説明が見られない旅がある | 公開データは公開時点のコピーで、後から作った動画・説明が反映されない | クラウド同期で公開データを作り直す。未アップロードの動画・写真は上げ直す |
| [x] 修正済み | 古地図の描画で、ヘルシンキの本土が海として塗られた | 海岸線が河口で途切れ、塗りつぶしが陸へ漏れた | 水面の輪郭も区切りに使い、領域ごとの多数決で判定 |
| [ ] 既知 | 中国の古地図・チェックポイントが、Google マップの背景と数百mずれて見える | 中国国内の地図は独自の座標系（GCJ-02）。アプリは GPS と同じ WGS84 で描いている | GPS の現在地とは一致する。背景に合わせるなら座標変換が必要 |
| [x] 修正済み | 自動一時停止から歩き出しても、Watch の画面が「一時停止中」のまま | 自動再開を画面の状態に反映していなかった | 自動再開の時に画面を「記録中」に戻し、iPhone にも再開を伝える（2026-09-27） |
| [x] 修正済み | 古地図・チェックポイントの一覧がアプリ（Swift）と Web（TypeScript）に二重に書かれていた | 二重管理 | `catalog/*.json`だけで管理し、両方のデータファイルを生成する形に変更（2026-09-27） |
